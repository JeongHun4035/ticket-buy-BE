추가로 생성 JAR `build/libs/ticket-buy-be-0.0.1-SNAPSHOT.jar`를 포트 18080과 독립 H2 메모리 DB로 기동했다. Flyway V1 마이그레이션 적용, 개발 시드 로딩, `/swagger-ui/index.html` 200, `/actuator/health` UP을 확인했다. `/v3/api-docs`를 UTF-8 `docs/openapi.json`으로 추출했고 OpenAPI 3.1.0, 29개 operation 및 정상 응답 예시를 확인했다. 검증용 서버는 종료했다. 기본 파일 DB가 이미 사용 중이어서 이를 사용하는 기존 프로세스는 변경하지 않았다.

PostgreSQL/Docker 실행 도구가 없는 환경이므로 PostgreSQL 엔진에서의 실행, 부하·장애 복구, 프론트 실제 화면 연동은 검증하지 않았다. PostgreSQL 재실행 방법은 README에 있다. 프론트 소스가 없어 TypeScript 예시는 프론트 프로젝트의 Vite 환경 타입과 함께 옮겨 타입 검사·화면 연동해야 한다. 실제 PG 결제는 구현·테스트 범위에 없다.

회원가입 추가 후 최종 JAR과 전체 9개 테스트를 다시 빌드·검증했다. 독립 DB/포트 18081로 최신 JAR을 기동해 `/auth/signup`의 201 성공 및 409 USERNAME_ALREADY_EXISTS 문서를 확인하고 `docs/openapi.json`을 갱신했다. 현재 API operation은 총 30개다.

조회 경로 분리 후에는 전체 16개 테스트와 JAR 빌드를 통과했다. 별도 H2 DB/포트 18081에서 최종 JAR의 실제 스케줄러가 최초 WAITING(position=1)을 ADMITTED로 자동 승격시키는 것을 HTTP로 확인했다. 대기 조회 200, 즉시 재조회 429, 입장 토큰을 사용한 좌석 조회 200 및 즉시 재조회 429, Cache-Control: no-store를 확인했다. V2 마이그레이션도 적용됐으며 최신 OpenAPI를 추출하고 검증용 서버를 종료했다. 이 검증은 동작/동시성 검증이며 대규모 부하 성능 측정이나 PostgreSQL 실환경 검증은 아니다.

층·구역 추가 후에는 전체 22개 테스트와 JAR 빌드를 통과했다. 최종 JAR을 독립 H2 DB/포트 18081에서 실행해 V3 적용과 신규 시드를 확인했다. 행사 10/20/30, 회차 1001/2001/3001에 실제 로그인·자동 대기열 입장 후 구역/구역 좌석 API를 호출했다. 공연장 capacity=500/5000/30000, 층=1/2/3, 구역=2/20/120, 선택 구역 반환 좌석=250, 초기 잔여 수 합=각 capacity를 확인했다. 민감 정보 없는 전체 응답을 `docs/examples`에 저장하고 OpenAPI(총 32개 operation)를 재추출했다. 검증용 서버는 종료했다. PostgreSQL 실제 엔진과 부하 성능은 검증하지 않았다.

이미지 첨부 행사 등록을 추가한 뒤에는 전체 25개 테스트를 통과했다. 실행 JAR/독립 H2 DB/포트 18081에서 관리자 로그인 후 실제 JPEG multipart 등록 201, 신규 행사/회차 ID 100000, 공개 JPEG 이미지 조회 200, 기존 dev 행사 8개 포스터 조회 200을 확인했다. Swagger에서 multipart event는 EventCreate 참조·application/json 인코딩, image는 string/binary 필수 필드임을 확인했다. OpenAPI(총 36개 operation)와 실제 등록 응답 `docs/examples/event-created.json`, 이미지 URL이 포함된 `venue-events.json`을 갱신하고 검증용 서버를 종료했다. 프론트 실제 화면·PostgreSQL 실환경·이미지 대량 트래픽은 검증하지 않았다.
